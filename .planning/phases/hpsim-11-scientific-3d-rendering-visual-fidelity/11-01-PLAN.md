# Plan 11-01: Scientific 3D Rendering & Visual Fidelity

## Goal

Implement the approved 3D visualization redesign for HPSim:
1. **Perfect Spherical Atoms**: High-fidelity sphere tessellation, uniform unit scaling, distortion-free atom spheres tracking Volterra displacement.
2. **Ghost Reference Lattice**: Static instanced mesh of faint white spheres displaying ideal unperturbed atomic lattice positions.
3. **Translucent Grain Boundary Plane**: Indigo 3D interface with violet-white outline, rendered only in multi-grain scenes with real boundaries.
4. **Gold-Based Orientation Color Coding**: Harmonized metallic gold palette for grains with dynamic cyan-white displacement magnitude highlighting.
5. **CSS2D World-Space Annotations**: Lightweight camera-facing labels anchored to dislocation core (`Dislocation core (⊥)`), grain boundary, slip plane, and Burgers vector.
6. **Burgers Vector Arrow**: Prominent crystallographically accurate slip direction arrow at dislocation core with world-space `b` tag.
7. **Depth, Lighting, and Composition**: 3-point scientific lighting setup and pulled-back camera framing for 15% breathing room.

All changes must preserve Phase 9 and Phase 10 completely. Single-crystal Chapter 1 must never show a grain boundary. Existing research dashboard controls and layer toggles must continue to work without regression.

---

## Architecture Constraints

- **Do not modify**:
  - `web/src/core/*` (dislocation fields, glide kinematics, boundary transmission, pileups, Hall–Petch)
  - Python codebase (`src/hpsim/*`, `tests/*`)
  - Material data files (`materials.yaml`, `materials.json`)
  - Phase 9 documentation (`.planning/phases/09-one-click-beginner-experience/*`)
  - Phase 10 documentation (`.planning/phases/10-four-chapter-interactive-learning-experience/*`)
- **Performance**:
  - Keep instanced rendering via `THREE.InstancedMesh`.
  - Ghost lattice must be static (computed once on `loadStructure`).
  - Zero memory leaks: cleanly dispose Three.js meshes, materials, and CSS2D DOM elements on viewer teardown.
- **Dependencies**:
  - Zero new npm dependencies; use Three.js and `three/examples/jsm/renderers/CSS2DRenderer.js` already bundled.

## Tasks

### Task 1: Atom & Ghost Lattice Manager (`web/src/render/atomMesh.ts`) [Agent B]
**Files created**: `web/src/render/atomMesh.ts`
- Implement `AtomMeshManager`:
  - Main atom mesh: `THREE.InstancedMesh` with high-tessellation `SphereGeometry(radius, 32, 24)` and `MeshStandardMaterial` (`color: 0xffffff, roughness: 0.32, metalness: 0.25`).
  - Ghost lattice mesh: `THREE.InstancedMesh` with `SphereGeometry(radius * 0.88, 16, 12)` and `MeshBasicMaterial({ color: 0xffffff, transparent: true, opacity: 0.14, depthWrite: false })`.
  - Instance positioning: strictly uniform dummy scale `(1, 1, 1)` and rotation `(0, 0, 0)` so spheres are never capsule-distorted.
  - Color palette: Grain 1 base gold (`0xd4a843`), Grain 2 base gold (`0xb8912e`).
  - Dynamic displacement color update: compute $\|\mathbf{u}_i\| = \sqrt{u_{x,i}^2 + u_{y,i}^2}$, normalize against reference threshold $b_m$, interpolate smoothly from base gold to cyan-white (`0xe0f2fe`).
