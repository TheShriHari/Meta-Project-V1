# Plan 10-01: Four-Chapter Interactive Learning Experience

## Goal

Transform HPSim from a research dashboard into an immersive, museum-installation quality four-chapter interactive science-learning experience ("Build intuition before equations. Let students discover what you want them to know.") as specified in `10-Brainstorm` and `10-Prompt`:
1. **Chapter 1 — The Defect**: Identify crystal lattice defects visually, start slow-motion edge glide under stress, modulate stress (Low → High), observe permanent plastic deformation, and understand what dislocations are before naming equations.
2. **Chapter 2 — The Wall**: Visualize two-grain boundary with amber interface plane, adjust grain misalignment (0° → 90°), evaluate Lee–Robertson–Birnbaum geometric compatibility via `evaluateBoundaryTransmission`, and observe honest TRANSMITTED / BLOCKED / UNRESOLVED outcomes.
3. **Chapter 3 — More Walls, More Strength**: Explore polycrystalline microstructure with grain size slider (Large → Small), predict outcome ("Smaller grains: stronger or weaker?"), run actual pile-up / Hall–Petch model, observe responsive Strength Meter, and log real runs into the persistent experiment drawer.
4. **Chapter 4 — The Pattern Has a Name**: Animate student's Chapter 3 data points onto a Hall–Petch chart, fit the trend, reveal $\sigma_y = \sigma_0 + k_y d^{-1/2}$ term-by-term with plain-English narration, test an extrapolative prediction, and unlock full Research Mode.

The existing advanced Research Dashboard (Phases 1–8) remains fully preserved and accessible via a persistent "Research Mode →" entry point.

---

## Architecture Constraints

- **Do not modify**: `web/src/core/*`, `web/src/render/*` (unless strictly read-only camera/annotation helper needed without changing physics), Python scientific files, fixtures, or existing tests.
- **Client-side only**: 100% client-side WebGL (Three.js), React 19, TypeScript, Vite. No backend, no extra npm packages.
- **Scientific honesty**:
  - Edge dislocations only in 3D glide; screw limitations declared honestly.
  - Domain limit in Chapter 1 is labelled accurately (not claimed to be a grain boundary).
  - Chapter 2 uses real `evaluateBoundaryTransmission` results.
  - Chapter 3 logs genuine calculated outputs from `runHallPetchSweep` / `solvePileupEquilibrium`.
  - Chapter 4 clearly distinguishes student-generated run data from literature-calibrated model curves.
